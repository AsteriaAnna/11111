# JD 定向简历内容

## 任务背景

本 skill 位于经历库整理之后、简历排版之前。经历库提供事实，JD 决定读者想看到的证明。目标是生成一份md格式的简历草稿，让面试官能从开头、项目标题与要点中迅速看出“此人为何适合这份工作”，并能沿每个模块继续追问。

## 必须执行的边界

- 完整读取经历库、JD 。缺 JD 时只可生成标明依据较弱的方向稿。
- 每个身份、技术、动作、数字和结果必须能回到资料。区分个人与团队、覆盖与注册、阶段率与累计人数、尝试与已采用。不得把工具接触写成独立开发，把宣传材料写成 PRD，把挂名写成实绩。
- 正式组织名、职位、日期保持原貌。描述性项目标题可根据 JD 突出**已证实**的方法或产物；不能为贴关键词添加未实现的技术。
- 姓名、联系方式、GitHub/作品链接、年龄、开源身份等只用已提供且适合投递的事实；缺失时在正文外提示，不编造。
- 简历正文和编辑说明分开；不在正文放“待确认”“资料未提供”等编辑备注。

## 工作流程

1. **确定读者要验证什么。** 从 JD 中提示的核心工作、交付物，门槛，任务、加分项和形容词中提炼该岗位需要的技能，能力，个人品质。对每项找经历库证据，标记为直接、可迁移、弱或缺失。
2. **先设计信息架构。** 写一句内部候选人定位，并确定最早出现的证据。把每段经历拆成事实和可追问模块，分别安排到身份定位、主项目、辅助经历、技能/作品链接或不使用。不要只对整段经历作保留/删除。项目重要性、个人角色与模块顺序由 JD 和证据决定；允许不同岗位采用不同结构。
3. **写成读者能扫懂的内容。** 优先呈现项目问题或价值，再界定本人负责范围，按与 JD 相交的模块、流程或阶段写判断、动作、产物与结果。短标签和顶部亮点只在它们帮助读者理解且不重复时使用。涉及多模块项目或身份定位时读 [呈现架构](references/presentation-architecture.md)；根据当前岗位只读 [岗位表达视角](references/expression-lenses.md) 中相关部分。
4. **按模板交付并反向检查。** 生成完整中文内容稿。起稿时读 [内容稿模板](assets/resume-content-template.md)，按证据增删栏目。只看开头、项目名、模块名和首条，检查能否说出候选人最强的岗位关联；逐项回查经历库中的责任范围、数据口径和结果，发现夸大或空泛则重写。

## 容易失真的地方

- 项目整体价值可以先说，但必须紧接本人角色，不能让团队成果看起来由个人完成。
- 同一经历可以在不同 JD 中成为主项目、辅助证据或一句真实身份；不要为“最大化利用”而重复同一事实或硬凑岗位术语。
- 复杂项目的模块名必须对应实际工作和可回答的面试问题。只列 middleware、skill、context 等名词而无本人实现与验证，不算模块证明。
- 没有直接证据的核心门槛要写进编辑说明；定位、标签和专业语气都不能填补它。
